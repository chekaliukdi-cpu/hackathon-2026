Суть задачі

Follow-up є. А хто це все зробить?

Після зустрічі бот із Задачі 2 надсилає підсумок. Але текст у чаті швидко губиться. Твій агент перетворює його на справжні задачі: кожна має власника й дедлайн і живе на дошці Trello, поки її не виконають.

01

Читає

Отримує follow-up зустрічі з кроку 2: підсумок, рішення і домовленості, хто що робить.

02

Аналізує

Мовна модель виділяє задачі. Кожна задача — це заголовок, відповідальний, дедлайн і короткий зміст.

03

Роздає

Надсилає список задач у Discord (коротко, без змісту) і створює для кожної картку в Trello через API.

Готового коду тут немає — так задумано. На сторінці є все, щоб зрозуміти, як працює агент, де взяти ключі Trello і які запити робити. Сам код ти напишеш разом із ШІ-асистентом.

Анатомія задачі

Чотири поля — і куди кожне йде

Агент збирає кожну задачу з чотирьох полів. Trello отримує все. Discord — тільки три: повідомлення в чаті має бути коротким, а подробиці лежать у картці.

ПолеПриклад Discord Trello
Заголовокtitle Зробити слайди презентації ✓✓
Відповідальнийassignee Макс ✓✓
Дедлайнdue «до п’ятниці» → 2026-11-06 ✓✓
Короткий змістdescription Слайди для презентації проєкту. Тексти бере в Дані. ✕✓

Дедлайн — це дата, а не слова. У follow-up пишуть «до п’ятниці», а Trello чекає точну дату. Модель не знає, який сьогодні день, поки ти їй не скажеш.

Не вигадуй. Якщо у follow-up немає відповідального чи дедлайну, агент має чесно написати «не визначено», а не підставити першого-ліпшого.

Шлях від follow-up до картки

П’ять етапів. Натисни на будь-який, щоб дізнатися, що там відбувається і які слова гуглити.

Відповідь — структурований список

Звичайний текст код не розбере. Попроси модель відповісти у форматі JSON: список задач, у кожної — заголовок, відповідальний, дедлайн і зміст. Багато API вміють «Structured output»: ти даєш схему, а модель гарантовано відповідає за нею. Перевір відповідь у коді, перш ніж іти далі.

Trello API

Як підключитися до Trello

Trello — це дошка з колонками й картками. Твій код керує нею через REST API: надсилає HTTP-запити й отримує відповіді в JSON. Спершу розберімося, з чого складається дошка.

Board · дошка
List · списокCard · картка
List
List
  • Дошка — проєкт, наприклад «Хакатон». Має свій id і учасників (members).
  • Список — колонка: «Треба зробити», «В роботі», «Готово». Картку створюють саме в списку, тому потрібен його id.
  • Картка — одна задача: назва, опис, дата (due) і учасники.

Запити, які знадобляться

Усі запити йдуть на https://api.trello.com/1/…, а ключ і токен додаються як параметри key і token. Перші три — щоб дізнатися id, четвертий — щоб створити картку.

GET/members/me/boards

Список твоїх дошок — знайди id потрібної.

GET/boards/{id}/lists

Списки дошки — знайди id списку «Треба зробити».

GET/boards/{id}/members

Учасники дошки та їхні id — щоб призначити відповідального.

POST/cards

Нова картка. Параметри: idList, name, desc, due, idMembers.

перевірка ключа і токена
# підстав свої значення; у відповідь має прийти JSON зі списком дошок
$ curl "https://api.trello.com/1/members/me/boards?fields=name&key=КЛЮЧ&token=ТОКЕН"

Документація. Повний опис усіх запитів — на developer.atlassian.com/cloud/trello. Там же ліміти: приблизно 100 запитів за 10 секунд на один токен — для задач після зустрічі цього з головою.

Хто є хто

Модель знає тільки імена з тексту. А для згадки в Discord потрібен ID користувача, для учасника картки в Trello — ID учасника дошки. Тож у коді знадобиться маленька «таблиця команди».

Ім’яDiscord IDTrello ID

Де взяти ID. Discord: увімкни режим розробника і клікни правою кнопкою на людину → «Копіювати ID». Trello: запит GET /boards/{id}/members. Справжня згадка в повідомленні виглядає як <@ID>.

Вайбкодинг

Як працювати з ШІ над цією задачею

Радимо робити задачу разом із Claude. Головний секрет цієї задачі — промпт для агента: що точніше опишеш формат відповіді, то менше доведеться виправляти.

Так собі

«Витягни інгредієнти з рецепта»

Модель відповість звичайним текстом, щоразу по-різному. Програма таку відповідь не розбере.
→
Набагато краще

«Ось текст рецепта. Поверни тільки JSON: список інгредієнтів, у кожного поля name (текст), amount (число) і unit (г, мл, шт). Якщо кількості в тексті немає — став null, нічого не вигадуй. Приклад: …»

Є точний формат, правило для пропусків і приклад. Цей самий прийом спрацює і для задач.
01

Частини окремо

Спершу картка в Trello вручну з коду. Потім JSON від моделі. Потім з’єднуй. Так одразу видно, яка частина зламалась.

02

Тестовий follow-up

Збережи 2–3 різні follow-up у файли, зокрема «складний»: без дедлайну, з двома відповідальними. Ганяй агента на них.

03

Дата в промпті

Модель не знає, яке сьогодні число. Передавай поточну дату в кожному запиті — інакше «до п’ятниці» стане випадковим днем.

04

Не давай ШІ ключі

Ніколи не вставляй справжній токен Trello чи Discord у чат з ШІ. Пиши TRELLO_TOKEN замість значення.

05

Читай відповідь API

Trello завжди пояснює помилку: код (400, 401, 404) і текст. Кидай ШІ і запит (без ключів!), і відповідь.

06

Проси пояснити

«Поясни цей код рядок за рядком». Тебе спитають, як агент вирішує, що є задачею, — маєш уміти розповісти.

Якщо щось не працює

Не готові відповіді, а підказки, куди копати.

Trello відповідає 401 «invalid key» або «unauthorized»
Чи не переплутав ти ключ і токен місцями? Чи немає зайвих пробілів чи лапок у .env? Чи токен створений саме для цього ключа? Перевір тим самим запитом через curl — якщо там працює, проблема в коді.
Картка не створюється: 400 або 404
Подивись текст відповіді. 404 часто означає неправильний idList — це id списку, а не дошки. 400 — щось не так із параметрами: перевір назви полів і формат дати.
Програма падає, коли розбирає відповідь моделі
Виведи сиру відповідь на екран. Модель могла загорнути JSON у ``` або дописати пояснення. Допоможе режим structured output / JSON mode і чітка фраза в промпті «відповідай тільки JSON». І завжди перевіряй відповідь перед використанням.
Дедлайн не той день чи навіть не той рік
Чи передаєш ти моделі сьогоднішню дату і день тижня? Чи просиш формат РРРР-ММ-ДД? Зверни увагу на часовий пояс: дата без часу може «з’їхати» на день. Перевір дату в коді, перш ніж надсилати.
ШІ призначає задачу людині, якої не було на зустрічі
Дай моделі список учасників і попроси обирати тільки з нього, а якщо відповідального немає — писати «не визначено». Зменш temperature. Перевір у коді, що ім’я є в «таблиці команди».
У Discord видно просто текст «@Макс», сповіщення не приходить
Справжня згадка пишеться через ID користувача, а не через ім’я. Подивись, як твоя бібліотека формує mention. Також перевір налаштування allowed mentions у повідомленні.
